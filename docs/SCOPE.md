# Scope «Матрикс» для хакатона MAX — трек «Образовательные решения»

## Целевая формулировка

**Целевая аудитория:** студенты 1–2 курса колледжа или вуза в период адаптации к учёбе, 18+. Возрастное ограничение снимает вопросы обработки персональных данных несовершеннолетних.

**Проблема** (по формуле ТЗ). Студент 1–2 курса в первые месяцы обучения хочет закрепить привычку регулярно посещать занятия и выполнять задания. Но ему не хватает эмоциональной обратной связи, и мотивация быстро спадает. Он пропускает пары и откладывает задачи, отстаёт и рискует отчислением.

**Основной сценарий (Must, демонстрируется целиком):**

1. Студент на паре сканирует QR с экрана преподавателя. Альтернативы — ввести 4-значный код в мини-приложении или отправить боту `/checkin 1234`.
2. Reward Service начисляет монеты, интеллект и настроение персонажа.
3. 3D-персонаж танцует, показываются «+N», растут шкалы. С ростом уровня растёт сам персонаж, открываются новые образы.
4. Бот MAX присылает уведомление с наградой, настроением персонажа, серией посещений и кнопкой «Посмотреть на персонажа».

## UX-фокусировка

- Первый экран — **«Сегодня»**: персонаж, карточка текущей пары с одной главной кнопкой («Сканировать QR» в мобильном MAX или ввод кода в веб-версии), серия посещений.
- Нижнее меню: Сегодня · Задачи · Привычки · Инвентарь · Ещё. Магазин, соцсеть, события, соревнования и статистика — в «Ещё».
- Шагов до отметки было 3 (Ещё → События → «Ввести код»), стало 1 при QR-диплинке и 1–2 внутри приложения.
- У каждого шага основного сценария явные состояния загрузки, успеха и ошибки: спиннеры, тосты, текст ошибки у поля ввода, «Повторить».

## Найденные и исправленные проблемы

| Проблема | Исправление |
|---|---|
| Рабочий токен бота и пароль БД захардкожены в `docker-compose*.yml` | Вынесены в `.env`. Для сдачи — новый репозиторий без истории, токен перевыпускается |
| `POST /lessons/{id}/attendance` без кода выдавал награду | Код обязателен, ручная отметка — только администратору |
| Код пары виден любому студенту (`qr_token` в списке пар и публичный `/qr`) | Код не хранится и не отдаётся; `/qr` — только администратору |
| Двойная отметка давала двойную награду | Уникальный ключ `(lesson_id, user_id)` + идемпотентный ответ `already` |
| Опасные эндпоинты открыты через gateway (`reset-database`, `/rewards/grant`, рассылки бота) | Блокировка в Caddy + `X-Admin-Token` + флаг `ALLOW_DB_RESET` |
| Админка защищена только паролем, зашитым в сборку фронтенда | Токен проверяется сервером и хранится в `sessionStorage` |
| Вход в мини-приложение доверял `initDataUnsafe` и ломался после 100 пользователей | `POST /users/auth/max` с проверкой HMAC-подписи |
| Каждое realtime-обновление пересоздавало 3D-сцену и заново качало модели | Сцена создаётся один раз |
| Время пар из формы сдвигалось на 3 часа | Наивное время трактуется как `APP_UTC_OFFSET_HOURS` |
| Отрицательные очки интеллекта (пропуск привычки) нарушали ограничение БД | Значение ограничено снизу нулём |
| Нет `.dockerignore`, в git лежит неиспользуемая модель на 40 МБ | Добавлены `.dockerignore`, модель удалена, фронт собирается через `npm ci` по `package-lock.json` |

## Допущения (не выдаются за факт)

- **Payload `bot_started`.** Типизирован в официальном TS-клиенте MAX, но не описан на странице документации. Запасной путь — текстовая команда `/start att-…`.
- **Кнопка `open_app`.** Формат поля `web_app` не проверен. По умолчанию используется link-кнопка `https://max.ru/<бот>?startapp=…` (`MAX_OPEN_APP_MODE=link`).
- **Нативная камера телефона.** Неизвестно, открывает ли она мини-приложение по ссылке `max.ru`. Гарантированный путь — «Сканировать QR» внутри приложения (`WebApp.openCodeReader`).
- **Порог «падения настроения».** В дашборде куратора это 15 пунктов за 7 дней — продуктовая гипотеза, требующая проверки на пилоте.
- **Демо-данные.** Статистика и расписание на стенде — смоделированные: `scripts/seed_demo.py` и `data/sample_schedule.csv`.
