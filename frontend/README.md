# Tamagotchi Metaverse Frontend (React)

Переработанный клиент Tamagotchi Metaverse на React + Vite. Интерфейс разделён на переиспользуемые компоненты, каждый крупный раздел изолирован и поставляется со своим состоянием и API-интеграциями.

## ⚡ Быстрый старт

### Через Docker (рекомендуется)

```bash
# В корне проекта запустить весь стек
docker-compose up --build -d

# Frontend будет доступен на http://localhost:3000
```

### Локальная разработка

```bash
cd frontend
npm install
npm run dev
```

По умолчанию Vite поднимает dev-сервер на `http://localhost:5173`. Все запросы проксируются на API Gateway (`http://localhost/api`).

**Важно:** Backend должен быть запущен (см. [QUICKSTART.md](../QUICKSTART.md))

### Сборка для продакшена

```bash
npm run build
npm run preview
```

## ✅ Готовые разделы

- **Аутентификация** – восстановление сессии из `localStorage`, автоматическое создание пользователя.
- **Персонаж** – 3D-просмотрщик на Three.js, отображение характеристик, обновление статов.
- **Задачи** – фильтры, создание/редактирование, генерация через AI, завершение/удаление, синхронизация с персонажем.
- **Привычки** – учёт периодов (daily/weekly/monthly), локальный кэш статуса, статистика по привычкам.
- **Инвентарь** – сетка предметов с визуализацией редкости и типов.
- **Достижения** – счётчики полученных достижений, список с прогрессом.
- **Магазин** – чтение текущих листингов (read-only).
- **Статистика** – сводные показатели из statistics-service.

> Разделы Social / Events / Competitions пока подключены к интерфейсу, но работают с заглушками. Структура компонентов и сервисов уже готова для внедрения соответствующих API.

## 🔌 API

Базовый URL определяется автоматически:

- `http://localhost/api` в dev-режиме
- `/api` в проде (за reverse-proxy)

Каждый домен имеет свой сервис (`src/services/*`), запросы делают через общую обёртку `apiClient`.

## 🧱 Архитектура

- **React Context** (`AppProvider`) хранит состояние пользователя, персонажа, активной секции и модалок.
- **useRefreshUserAndCharacter** – общий хук для синхронного обновления данных пользователя и персонажа.
- **Features-first** структура: у каждой фичи есть собственные компоненты, сервисы и модалки.
- **Three.js** интегрирован в `CharacterViewer` через `useEffect` с корректным cleanup.

## 🗂 План расширения

- Social: добавить загрузку кланов/друзей/групп из `social_service`.
- Events: подключить списки событий и регистрацию.
- Competitions: вывести челленджи и глобальные соревнования, добавить действия.
- Shop: реализовать покупку/листинги, модалки трейда.
- UI feedback: подключить toast-систему (сейчас заглушка).

## 🧪 Советы по тестированию

1. Запустите все backend-сервисы (`docker-compose up`).
2. Создайте пользователя через экран логина.
3. Проверьте создание задач/привычек, завершение задач, синхронизацию монет/интеллекта.
4. Убедитесь, что статистика обновляется после действий.
